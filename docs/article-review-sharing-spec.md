# 記事レビュー共有機能 仕様書

## 1. 概要

作成済みの記事を、外部の確認者へ安全な共有リンクで渡し、記事本文に対するコメント、編集、および変更履歴の確認を可能にする。

本機能は記事の公開機能とは独立した**レビュー工程**として扱う。共有リンクを知る人だけが、発行時に指定された範囲で記事を閲覧・レビューできる。

## 2. 目的

- 社内外の確認者が、アカウント登録なしで記事を確認できるようにする。
- 本文の特定箇所に紐づくコメントを残せるようにする。
- 必要に応じて確認者が直接編集できるようにする。
- 誰が、いつ、何を変更したかを記録し、以前の版へ戻せるようにする。
- 記事一覧や他の記事を外部へ公開しない。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 所有者 | AutomaticWriterにログインして記事を管理する利用者。 |
| 確認者 | 共有リンクを使って記事を確認する外部ユーザー。 |
| 共有リンク | ランダムなトークンを含む、特定の記事だけを開くURL。 |
| コメントスレッド | 本文の選択範囲に紐づく親コメントと返信のまとまり。 |
| リビジョン | ある時点のタイトル・抜粋・本文を保存した記事の版。 |

## 4. 対象範囲

### 4.1 MVPで提供する機能

1. 所有者による共有リンクの発行・無効化
2. 共有権限（閲覧のみ／コメント可／編集可）の設定
3. 外部向け記事プレビュー画面
4. 文章をドラッグ選択して投稿するコメント
5. コメントへの返信、解決、再オープン
6. 編集可リンクからのタイトル・抜粋・本文の編集と自動保存
7. 記事リビジョンの一覧、差分表示、復元
8. 共有リンクの有効期限と任意パスワード

### 4.2 MVPでは対象外

- Google Docsのような同時編集カーソル表示
- 通知メール、Slack通知
- 変更提案の一括採用・却下
- 添付ファイル、画像へのピンコメント
- 個別メールアドレスを指定した招待・ログイン必須のレビュー

これらはMVPの利用状況を踏まえ、次フェーズで追加する。

## 5. 権限

| 権限 | 記事閲覧 | コメント投稿・返信 | コメント解決 | 記事編集 | 履歴閲覧 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 閲覧のみ | ○ | × | × | × | × |
| コメント可 | ○ | ○ | 自分のコメントのみ | × | × |
| 編集可 | ○ | ○ | 自分のコメントのみ | ○ | × |
| 所有者 | ○ | ○ | ○ | ○ | ○ |

確認者は初回利用時に表示名を入力する。表示名はその共有リンク内で保持し、コメント・編集履歴の投稿者として表示する。

## 6. 画面仕様

### 6.1 所有者側：記事編集画面

既存の`ArticleEditor`に「レビュー共有」入口を追加する。

- 共有リンク一覧（状態、権限、有効期限、最終アクセス日時）
- 「共有リンクを作成」ダイアログ
  - 権限（必須）
  - 有効期限（任意）
  - パスワード（任意）
- URLのコピー
- リンクの無効化／再発行
- 未解決コメント数の表示
- 「コメント」「履歴」パネルへの入口

### 6.2 確認者側：レビュー画面

URL形式：`/review/:token`

画面は、左に記事、右にコメントパネルを置く。モバイルではコメントを下部シートまたは別タブで表示する。

- ヘッダー：記事タイトル、レビュー権限、コメント表示切替
- 記事領域：Markdownをレンダリングした読み取り表示
- コメント可の場合：本文をドラッグ選択すると「コメントを追加」を表示
- 右パネル：未解決／解決済みを切り替えられるコメント一覧
- 編集可の場合：「編集」切替でタイトル・抜粋・本文を編集可能
- 保存状態：「保存中」「保存済み」「保存に失敗」を表示

### 6.3 コメント操作

1. 確認者が本文内の文字列をドラッグ選択する。
2. 選択範囲の近くに「コメントを追加」ボタンを表示する。
3. コメント入力欄で本文を入力し、投稿する。
4. 対象範囲をハイライトし、右パネルにスレッドを作る。
5. 所有者または投稿者がスレッドを解決できる。

タイトルと抜粋にもコメントを付けられるよう、これらはそれぞれ選択可能な表示領域として扱う。

## 7. コメントの位置特定

本文は編集により文字位置がずれるため、単純な開始・終了文字数だけではコメントを安定して表示できない。各コメントには次を保存する。

- 対象フィールド：`title`、`excerpt`、`content`
- 選択文：`selected_text`
- 選択範囲の開始・終了オフセット
- 選択文の前後各80文字程度の文脈
- コメント作成時点のリビジョンID

表示時は、まずオフセットで一致確認を行い、不一致なら「選択文＋前後文脈」で再検索する。再特定できない場合、コメントは一覧に残し、「対象箇所は変更されました」と表示する。

## 8. 編集・保存・履歴

### 8.1 保存

- 外部編集は入力停止後1秒で自動保存する。
- 画面離脱前に未保存の変更があれば警告する。
- 保存競合を避けるため、更新時に記事の`updated_at`またはリビジョン番号を照合する。
- 他者の変更後に保存しようとした場合は、自動上書きをせず、最新内容との差分を示して選択を求める。

### 8.2 リビジョン作成

以下の操作でリビジョンを作成する。

- 所有者による明示保存
- 確認者の自動保存（本文・タイトル・抜粋に実際の変更がある場合）
- 所有者による過去版の復元

各リビジョンには、タイトル、抜粋、本文、変更者、変更日時、変更元、任意メモを保存する。

### 8.3 履歴画面

- 新しい順にリビジョンを表示する。
- 任意の2版を選び、タイトル・抜粋・本文の行単位差分を表示する。
- 所有者のみ「この版に復元」を実行できる。
- 復元は新たなリビジョンとして記録し、履歴を削除しない。

## 9. データ設計

### 9.1 `article_review_links`

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `article_id` | uuid | 対象記事 |
| `token_hash` | text | 共有トークンのハッシュ値。生トークンは保存しない。 |
| `permission` | text | `view` / `comment` / `edit` |
| `password_hash` | text nullable | 任意パスワードのハッシュ値 |
| `expires_at` | timestamptz nullable | 有効期限 |
| `revoked_at` | timestamptz nullable | 無効化日時 |
| `last_accessed_at` | timestamptz nullable | 最終アクセス日時 |
| `created_at` | timestamptz | 作成日時 |
| `created_by` | uuid nullable | 作成者 |

### 9.2 `article_comments`

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `article_id` | uuid | 対象記事 |
| `review_link_id` | uuid | 利用した共有リンク |
| `parent_id` | uuid nullable | 親コメント。`null`ならスレッドの先頭。 |
| `field` | text | `title` / `excerpt` / `content` |

| `start_offset` / `end_offset` | integer nullable | 選択位置 |
| `prefix_context` / `suffix_context` | text nullable | 再特定用の文脈 |

### 9.3 `article_revisions`

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |

## 10. API・アクセス制御

外部画面は、`articles`テーブルをブラウザから直接参照しない。Supabase Edge FunctionまたはNetlify Functionを経由し、共有トークンを検証してから必要最小限のデータを返す。

### APIの責務

| 操作 | 利用者 | 概要 |
| --- | --- | --- |
| 共有リンク発行・無効化 | 所有者 | 管理画面の認証を確認して実行 |
| レビュー情報取得 | 確認者 | トークン、期限、失効、パスワードを検証 |
| コメント作成・更新 | 確認者 | `comment`または`edit`権限を検証 |
| 記事編集 | 確認者 | `edit`権限と競合条件を検証 |
| 履歴取得・復元 | 所有者 | 記事所有者であることを検証 |

### セキュリティ要件

- 共有トークンは暗号学的に安全な乱数で生成し、DBにはハッシュのみを保存する。
- URLが漏れても、無効化・期限切れ・パスワードでアクセスを止められるようにする。
- 共有APIは対象の記事だけを返し、記事一覧・AI設定・WordPress設定・他の共有リンクを返さない。
- レート制限を設け、トークン総当たりを防ぐ。
- コメント本文はMarkdownを許可する場合でも危険なHTMLを無効化し、XSSを防ぐ。
- 現在の`articles`のpublicアクセス許可ポリシーは、外部共有のリリース前に認証済み所有者のみへ制限する。

## 11. 例外・エラー表示

| 状態 | 表示 |
| --- | --- |
| 不正・存在しないURL | 「この共有リンクは利用できません」 |
| 期限切れ | 「この共有リンクの有効期限は終了しました」 |
| 無効化済み | 「この共有リンクは無効になりました」 |
| パスワード不一致 | 「パスワードが正しくありません」 |
| 権限不足 | 「この操作を行う権限がありません」 |
| 保存競合 | 「他の変更があります。内容を確認してから保存してください」 |
| 対象箇所を再特定できないコメント | 「対象箇所は変更されました」 |

## 12. 受け入れ条件

1. 所有者が記事単位でコメント可の共有リンクを作成・コピー・無効化できる。
2. リンクを受け取った確認者は、他の記事を閲覧できない。
3. 確認者は本文の一部を選択してコメントを投稿でき、選択範囲が視覚的に分かる。
4. コメントの返信、解決、再オープンができる。
5. 編集可リンクの確認者が変更すると、変更者・日時・変更前後の内容が履歴に残る。
6. 所有者は履歴から任意の版を復元でき、復元自体も履歴に残る。
7. 期限切れ・無効化済み・権限外のリンクでは、記事本文およびコメントを取得できない。
8. 現行の記事生成、記事編集、WordPress公開の既存機能が維持される。

## 13. 実装順序

1. 認証・RLSの見直しと新規テーブルのマイグレーション
2. 所有者側の共有リンク管理
3. トークン検証用のサーバーAPIと外部プレビュー画面
4. 範囲選択コメントとコメントパネル
5. 外部編集・自動保存・競合検出
6. リビジョン・差分・復元
7. テスト、リンク無効化・期限切れ・権限ごとの検証
