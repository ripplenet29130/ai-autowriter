# 記事の質を上げる改善プラン

作成日: 2026-11-10
ステータス: たたき台（実装前・決定待ち）

## 1. 目的

Claude や ChatGPT のアプリで人が作る記事と同じ水準の記事を、オートライターで自動的に作れるようにする。

## 2. 今の状態（コードで確認したこと）

質を下げている原因は、AI そのものではなく、アプリが AI にかけている制限にある。

## 4. 進め方

### 段階 0: 今の質を測る（半日）

改善の前後を比べられるようにする。

- キーワードを 5 個決める
- 今の設定で 5 本作って保存する
- 同じキーワードを Claude アプリでも 1 回ずつ作って保存する（目標の基準にする）
- 評価の観点を決める: 具体性、重複の少なさ、つながり、事実の正確さ、読みやすさ

終わりの条件: 5 本ずつの記事と、観点ごとの評価が残っている。

### 段階 1: 今の仕組みのまま直す（1〜2 日）

自動投稿と手動生成の両方に適用する。

| # | 内容 | 対応する原因 |
|---|---|---|
| 1-0 | 文字数おまかせ（4.1）。書く前に、AI が記事の長さと見出しの数を決める | C・E |
| 1-1 | 機械的な削除をやめる。上限を超えたときだけ AI に「内容を保ったまま短く」と書き直させる。時間がなければ削らずそのまま出す | C |

| 1-4 | 小見出しの機械的な差し込みをやめる。小見出しが必要かどうかは構成案と執筆の段階で AI に決めさせる | H |
| 1-5 | セクション執筆のとき、前のセクションの本文を全文渡す。並列をやめて順番に書く設定を選べるようにする | G |

終わりの条件: 段階 0 と同じ 5 個のキーワードで作り直し、評価が上がっている。

#### 4.1 文字数おまかせ

考え方: 書いてから削るのをやめ、書く前に量を決める。内容を選ぶのはプログラムではなく AI にする。

流れ:

1. **長さを決める**: 調査（検索意図・読者の疑問・上位記事の分量）をもとに、AI が「このキーワードに適切な文字数」と理由を出す
2. **内容を絞る**: 調査で見つけた話題と根拠のうち、検索した人の疑問に直接答えるものを優先して選ぶ。外れる話題は使わない（1-8）
3. **見出しの数を合わせる**: 1 見出しあたり 250 字以上になるように見出しの数を決める（1-7）
4. **書く**: 決めた文字数を目安として伝える。段落数・文の数は固定しない（1-2）
5. **超えたとき**: 決めた文字数の 1.5 倍を超えたときだけ、AI に短く言い直させる（1-1）。機械的な削除はしない

決まり:

| 項目 | 内容 |
|---|---|
| 既定 | 新しく作るスケジュールと手動生成は「おまかせ」。既存のスケジュールは今の文字数指定のまま（自動では変えない） |
| 選び方 | スケジュール設定と手動生成画面で「おまかせ／文字数指定」を選べる |
| 下限と上限 | 1,500〜6,000 字（費用と時間が増えすぎないようにする。上限は設定で変えられる） |
| 文字数指定のとき | 2〜5 は同じ。1 だけ行わず、指定の文字数を使う |
| 記録 | AI が決めた文字数と理由を、品質レポートと通知に出す |

注意:

- 記事ごとに長さ・費用・時間がばらつく。長い記事は無料の Supabase（140 秒）では書ききれず、見直しや検証の省略が増える。おまかせを自動投稿で本格的に使うには、3 章の 3（Supabase の有料化）か段階 4（新方式）が必要になる可能性が高い
- 今の流れ（SerpAPI の競合調査）では上位記事の分量が正確に分からない。見出しの数と検索意図から決める
- DB にスケジュールの設定を 1 つ足す（文字数が空ならおまかせ、という扱いにできるかは実装時に確認する）

注意:
- 1-3 と 1-5 は時間が延びる。無料の Supabase（140 秒）では編集見直しの省略が増える可能性がある。省略が増えたら 3 章の 3 を決める。
- 1-3 は費用が上がる。実際のトークン数は通知の費用欄で確認する。

### 4500 字での再テストの結果（2026-11-10 13:13、同じキーワード 1 本）

`experiments/pipeline-compare/out/20261110-131357/` の結果。

| | 今の流れ | 新しい流れ |
|---|---|---|
| 質の採点（平均） | 4.33（2000 字のとき 4.5） | **4.67**（2000 字のとき 4.0） |
| 具体性 | 4 | **5** |
| 重複の少なさ | 3 | 4 |
| 並べ比べ | **勝ち** | 負け |
| 事実確認（正しい／一部誤り／誤り） | 15／3／1 | 17／2／1 |
| 機械的な削除 | 5706 → 4830 字 | 6292 → 5402 字（見出し 1 個が消えた） |
| 編集見直し | 時間切れで省略 | 不採用（5955 → 7288 字、22% 増） |
| 検証の検索 | 8 件を時間切れで省略 | 省略なし |
| 時間 | 約 2 分 44 秒 | 約 14 分 31 秒 |
| Gemini の費用 | 約 63 円 | 約 156 円（＋ ChatGPT 分） |

分かったこと:

- 削除が減ると、新しい流れの質の採点は今の流れを上回った（4.0 → 4.67）。削除が主な原因だったという見立ては、採点の点数では裏付けられた。
- ただし並べ比べでは今の流れが勝った。理由は「新しい流れは窓口の受付時間など、期限そのものから外れる細部が多く、話が広がりすぎている」。調査が充実した分、検索意図から外れる内容まで入れている。
- 4500 字でも削除は起きた。構成案が目標に合わせて 22 個に増え、本文が目標の 1.3〜1.4 倍になったため。
- 編集見直しは 2 回とも文字数の条件で不採用。新しい流れでは一度も効いていない。
- 並べ比べは 2 回とも「今の流れが 1 番目」の並びだった。並び順の影響を受けている可能性がある。
