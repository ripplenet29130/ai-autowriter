# 記事作成の比較テスト（今の流れ ／ 新しい流れ）

同じキーワードで「今の流れ」と「新しい流れ（v2 仕様のお試し）」を実際の API で動かし、
同じ ChatGPT で採点して、比較ページ（HTML）を作ります。

- アプリ・DB・WordPress・通知には一切触れません（記事は投稿されません）。
- アプリ本体のファイルは変更していません。今の部品を読み込んで使うだけです。

## 準備

1. `.env.example` をコピーして `.env` を作り、キーを入れる（`.env` は Git に入りません）
   - 必須: `GEMINI_API_KEY`、`OPENAI_API_KEY`
   - 今の流れの競合調査に使う: `SERPAPI_API_KEY`（なければ競合調査なしで動きます）
   - SerpAPI の代わりに SearchApi（searchapi.io）を使う場合: `SEARCHAPI_API_KEY`（入っていればこちらを優先。ページの見出しの読み取りは本番と同じ処理）
2. Node.js が入っていれば OK です（Deno は `npx` で自動的に使います）

## 実行

プロジェクトのフォルダ（`ai-autowriter`）で実行します。キーワードは複数並べられます。

```bash
npx -y deno@2.9.6 run --allow-net --allow-env --allow-read --allow-write --env-file=experiments/pipeline-compare/.env experiments/pipeline-compare/run.ts "相続税 申告期限" "NISA 始め方"
```

オプション:

| オプション | 内容 |
|---|---|
| `--words 3000` | 目標文字数（既定は本番と同じ） |
| `--only current` / `--only v2` | 片方だけ動かす |
| `--no-judge` | 採点をしない |
| `--baseline 20261110-122307` | 今の流れだけを動かし、`out/` に保存してある以前の結果（同じキーワードの「今の流れ」の記事）と比べる。並べ比べは記事の順番を入れ替えて 2 回行う |

`--words` を付けないと、今の流れは本番の新しい既定と同じ「文字数おまかせ」（AI が文字数を決める）で動きます。
本文を順番に書く設定を試すときは、`.env` に `SECTION_WRITING_MODE=sequential` を入れます。

結果は `experiments/pipeline-compare/out/日時/` にできます。

- `report.html`: 比較ページ（ブラウザで開く）
- `result.json`: すべての結果
- `キーワード-current.md` / `キーワード-v2.md`: 完成した記事

1 キーワードあたり 5〜10 分ほどかかります。

## 2 つの流れの違い

| | 今の流れ | 新しい流れ |
|---|---|---|
| 競合調査 | SerpAPI で上位 5 件を取得し、ページの見出しを読み取る | Gemini が Google 検索し、上位記事を自分で読んで検索意図・見出し・読者の疑問・足りない点をまとめる |
| 根拠集め | Gemini 検索（40 秒で打ち切り、競合調査と同時） | Gemini 検索（打ち切りなし、調査結果を踏まえて） |
| 本文 | H2 ごとに並列で書く | H2 ごとに順番に書く（前のセクションとつなげる） |
| 時間制限 | 本番と同じ 140 秒。足りなければ見直し・検証を省略する | なし（本番では工程ごとに分けて実行する想定） |
| 検証 | Gemini（Google 検索） | ChatGPT（Web 検索）。修正は Gemini、再検証は ChatGPT、最大 2 回 |

## 採点の方法

最後に ChatGPT が、両方の記事を**同じ条件**で採点します。

1. 事実確認: 根拠メモを渡さずに、記事だけを Web 検索で確認します（誤り・一部誤り・確認できずの件数）
2. 質の採点: 検索意図への答え、具体性、構成、重複、日本語、信頼できる書き方を 5 段階で採点します
3. 並べ比べ: 2 つの記事を並べて、どちらが読者の役に立つかを判断します（記事の並び順は毎回ランダム）

注意: 新しい流れは途中で ChatGPT の検証を受けて直しているため、ChatGPT による事実確認では有利になりやすいです。
差を見るときは、「今の流れで ChatGPT が見つけた誤りが、本当に誤りか」も確認してください。

## 本番と違う点

- 今の流れの競合調査は、本番では先に専用の Edge Function（`competitor-search`）を試します。ここでは直接 SerpAPI を呼ぶ方式（本番の予備の方式）を使います。
- 本番の自動投稿では、本文の整形に `index.ts` 内の専用処理も使いますが、外から呼べないため、公開前の正規化処理で代わりにしています（両方の流れで同じものを使います）。
- プロンプトセット・文体参照 URL は使いません（両方とも同じ条件）。
- 費用は Gemini を有料キーの単価で計算します。OpenAI は `.env` に単価を入れた場合だけ計算します。SerpAPI の費用は含みません。
